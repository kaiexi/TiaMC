## 2. 虚拟机软件（VMware/VirtualBox 一类）的通用范式

我没有它的规范文档，但这一类软件的交互是稳定且公认的：

1. **库（Library）**：左边一列"库 / 收藏夹"，列出所有虚拟机（= 我们的 Minecraft 实例）。
2. **主页 + 大预览**：中间主区上半是实例的**大预览/摘要卡片**（截图、状态、快照数），下半是**选项卡**（概要 / 快照 / 日志 / 设置）。
3. **属性/明细（Detail）**：右侧一列显示选中实例的明细（CPU/内存/磁盘/网络/路径）。
4. **控制台（Console）**：底部或独立区域显示**实时输出**，可以输入命令（我们的服务端已经能做，客户端控制台也已有）。
5. **生命周期操作**：`启动 / 关机 / 挂起 / 重启 / 快照(创建/恢复/删除) / 克隆 / 移动 / 打开目录 / 移除`。

把 Minecraft 实例**当成虚拟机**来看，映射关系天然成立：

| 虚拟机概念 | Minecraft 对应 |
|---|---|
| 客户机操作系统版本 | 游戏版本 + 加载器（Forge/NeoForge/Fabric/OptiFine…） |
| 虚拟磁盘 | `.minecraft` 实例目录（`versions/<id>` + 存档/资源包/模组） |
| 内存/CPU 分配 | `-Xmx/-Xms`、JVM 参数、Java 运行时 |
| 网络（NAT/桥接） | 离线账户 / 正版账户 / 认证服务端(authlib-injector) |
| 快照（Snapshot） | 实例目录 + 配置的**打包快照**（一键回滚） |
| 克隆（Clone） | 复制实例（完整克隆 / 链接克隆=共享只读资源） |
| 控制台 | 启动器的控制台面板（客户端日志 / 服务端 stdout） |
| 共享文件夹 | 资源包/存档的共享目录 |

**要点**：
* 外观**不变博途味**（功能区 + 项目树 + 属性 + 输出窗口 + 状态栏）；
* 项目树从"设备与网络"改成 **库（Library）** 语义：顶层分组 `实例 / 服务器 / 整合包 / 快照`；
* 工作区新增两个标签：**快照**、**设置（实例设置）**；控制台保留；
* 右侧属性面板改成虚拟机那种**明细表**（内存滑杆 + Java + 路径 + 磁盘占用）；
* 顶部功能区加四个**虚拟机操作**：`启动 / 停止 / 快照 / 克隆`。

## 5. 需要你确认的三点

1. **库的分组**要按什么分？`实例 / 服务器 / 整合包 / 快照`（我建议），还是保持博途的 `设备与网络`？
2. **快照范围**默认要不要含模组 jar（含=体积大但可完整回滚；不含=省地方，但模组变了回不去）？
3. **克隆默认**用完整克隆还是链接克隆？（我建议默认完整克隆，链接克隆作为高级选项）
